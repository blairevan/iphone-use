# 安全加固收口设计

授权：用户已要求实施此前审查的安全方案，并要求完成后统一汇报。
本轮沿用该范围，不开启公网入口、不替用户信任发布公钥、不触碰手机任务，
不引入第三方依赖。已有未提交的本任务修改保留并继续验收。

## 不变量

1. 无人值守只检查版本，不执行任何新代码、更新 skill、重签或安装。
2. 手动发布安装使用已安装的验证器、独立导入的信任根、完整签名清单、
   私有暂存和现有安装事务。先验证所有资产，再执行；未知根、过期、降级、
   不完整包均拒绝。旧的网络 bootstrap 不再有执行通路。
3. 初始信任根指纹由操作者经独立渠道核对。不得把同一下载源返回的密钥
   直接当作可信根，也不得生成本机测试密钥冒充上游发布者。
4. 远程能力需要显式配置已有、可验证的 HTTPS 入口；默认仍仅回环。
   本机 HTTP、反向代理 HTTPS、中继各自具有明确的传输来源。
   未验证的候选地址不接收凭据；迁移失败保留旧地址与密钥。
5. 设备、浏览器会话和新 agent 凭据有独立的可撤销身份。撤销在认证层
   检查并持久化，不只是隐藏前端条目；遗留共享凭据明确标记为共享。
6. 下载的 flow 不能为自己授予免确认权限；审批固定到精确内容与输入。
   不宣称能够通过 JSON 或模型完全判断 UI 的现实副作用。
7. 默认日志只含结构化运行信息，不写屏幕文字、输入、HTTP body 或凭据。
   高权限管理操作需新鲜管理员认证，且产生最小化审计记录。

## 实施与验证顺序

1. 关闭遗留手动下载/skill 刷新旁路；补齐离线签名发布验证、信任根轮换、
   版本/序列/过期检查，以及完整文件清单和暂存执行。使用现有 ring/serde。
2. 补齐持久凭据登记与撤销、管理 API/界面、可信传输元数据、远程配置与
   身份验证探测。防止 relay 重放把远程请求伪装成本机。
3. 修复已发现的日志泄露、凭据命令行参数、flow/任务/调度确认绕过及续期
   身份漂移；补失败、重放、并发与命名实例测试。
4. 只格式化本任务改动；运行全 Rust 测试、安装/卸载/更新回归、Swift
   本机夹具、真实回环 HTTP/HTTPS 协议测试及发行构建。缺少真机或平台运行时
   时如实记录，不能用 mock 冒充真机验收。
5. 完成独立第二遍差异审查与部署检查，更新安全文档及验证记录，再统一汇报。

## 自审

采取“阻断未受信任代码 + 显式离线安装”，而不是继续信任 GitHub 同源哈希。
签名封装使用精确字节和独立域分隔；不自称完整 TUF 实现。
根轮换同时由旧根和新根满足各自阈值，且版本逐一递增；新的发布密钥集
撤销旧密钥，发布清单必须符合最新根。代码不能代替组织的签名密钥治理。
HTTPS 入口的证书签发与续期由用户选择的 TLS 终止服务负责，客户端每次
连接进行系统证书验证；不会安装“信任所有证书”的回退。

设计参考：The Update Framework Specification 1.0.36（root rotation、
rollback/freeze 防护）；Apple Performing manual server trust authentication。
